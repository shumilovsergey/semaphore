## Роль `autossh`

Делает из списка `autossh_tunnels` по одному systemd-сервису на туннель:
`/etc/systemd/system/<name>.service`.

`autossh` должен быть **уже установлен** на хосте — роль его не ставит, а проверяет наличие и падает с понятной ошибкой, если его нет.

Раньше такие юниты писались руками и отличались друг от друга только именем,
портами, адресами и тем, наружу открыт порт или только на localhost — теперь это данные в `servers/<hostname>.yml`.

### Переменные

Общие (`defaults`, перебиваются в файле сервера):

| Переменная | По умолчанию | Что это |
|---|---|---|
| `autossh_user` | `sh` | системный пользователь, от которого работает сервис |
| `autossh_ssh_user` | `sh` | пользователь для коннекта на удалённый хост |
| `autossh_ssh_key` | `/home/{{ autossh_user }}/.ssh/id_rsa` | приватный ключ |
| `autossh_default_type` | `L` | тип туннеля по умолчанию |
| `autossh_default_bind` | `127.0.0.1` | адрес прослушивания по умолчанию |
| `autossh_default_dest_host` | `127.0.0.1` | куда пробрасывать по умолчанию |
| `autossh_server_alive_interval` | `30` | `-o ServerAliveInterval` |
| `autossh_server_alive_count_max` | `3` | `-o ServerAliveCountMax` |
| `autossh_strict_host_key_checking` | `accept-new` | `-o StrictHostKeyChecking` |
| `autossh_restart_sec` | `5` | `RestartSec` в юните |
| `autossh_tunnels` | `[]` | список туннелей |
| `autossh_tunnels_absent` | `[]` | имена туннелей, которые нужно удалить с хоста |

Поля туннеля:

| Поле | Обяз. | Что это |
|---|---|---|
| `name` | да | имя сервиса → `<name>.service` |
| `listen_port` | да | порт, который открывается |
| `ssh_host` | да | адрес сервера, к которому идёт ssh |
| `type` | нет | `L` — обычный, `R` — обратный |
| `bind` | нет | `0.0.0.0` — порт виден из сети, `127.0.0.1` — только с самой машины |
| `dest_host` | нет | куда пробрасывать, по умолчанию `127.0.0.1` |
| `dest_port` | нет | по умолчанию равен `listen_port` |
| `user`, `ssh_user`, `ssh_key` | нет | перебивают общие значения для одного туннеля |
| `description` | нет | своё описание в `[Unit]` |
| `options` | нет | список доп. `-o` опций ssh, например `["Compression=yes"]`. Нестандартный порт ssh — тоже сюда: `["Port=2222"]` |

### Пример в `servers/<hostname>.yml`

```yaml
server_roles:
  - autossh

autossh_user: sh
autossh_ssh_user: sh
autossh_ssh_key: /home/sh/.ssh/id_rsa

autossh_tunnels:
  # порт 35152 удалённого хоста открыт наружу на этой машине
  - name: awg-vpn-reserv
    type: L
    bind: 0.0.0.0
    listen_port: 35152
    dest_port: 35152
    ssh_host: 5.189.254.175

  # то же, но доступно только с самой машины
  - name: pg-remote
    type: L
    bind: 127.0.0.1
    listen_port: 5433
    dest_port: 5432
    ssh_host: 5.189.254.175

  # обратный: локальный 8080 становится 127.0.0.1:8080 на удалённом хосте
  - name: expose-app
    type: R
    bind: 127.0.0.1
    listen_port: 8080
    dest_host: 127.0.0.1
    dest_port: 8080
    ssh_host: 5.189.254.175

# убрать туннель с хоста: сервис остановится, unit удалится
autossh_tunnels_absent: []
```

### Что делает роль

1. Проверяет туннели до любых изменений: имена уникальны, есть `name`/`listen_port`/`ssh_host`, `type` только `L`/`R`, пользователь существует, ключ лежит на месте, `autossh` установлен.
2. Раскладывает unit-файлы, делает `daemon-reload`.
3. Первый запуск — `started`, изменившийся unit — `restarted`, без изменений — не трогает.
4. Проверяет, что сервис `active`, и для `L`-туннелей — что порт реально слушается.
5. Всё из `autossh_tunnels_absent` останавливает, выключает из автозапуска и удаляет.

### Важно

- **Просто удалить строку туннеля из файла сервера — недостаточно.** Ansible видит только то, что есть в списке: unit останется на диске, сервис останется в автозапуске и продолжит работать. Чтобы убрать туннель — впиши его имя в `autossh_tunnels_absent`, прогони роль, потом можно удалить и оттуда.
- **Пользователь.** Вопреки правилу «все сервисы от `service_ansible`» (`tools/RULES.md`), туннель работает от обычного пользователя: ему нужен читаемый приватный ключ, а у `service_ansible` `nologin` и нет home. Если захочется перевести на `service_ansible` — надо положить ключ в `/etc/autossh/id_rsa` с владельцем `service_ansible` и задать `autossh_user`/`autossh_ssh_key`.
- **Ключ должен быть без пароля** и уже прописан в `authorized_keys` на удалённом хосте — сервис неинтерактивный.
- **`bind: 0.0.0.0` — это открытый порт.** Firewall роль не трогает, порт нужно добавить в `nft_allow_input_extra` в том же файле сервера.
- **Обратный туннель (`R`) с `bind: 0.0.0.0`** будет слушать наружу только если на удалённом sshd стоит `GatewayPorts yes` (или `clientspecified`). Иначе он всё равно поднимется на loopback.
- **Первый коннект.** `StrictHostKeyChecking=accept-new` означает, что ключ незнакомого хоста принимается автоматически, а подмена уже известного — по-прежнему ошибка. Если так нельзя — поставь `yes` и разложи `known_hosts` заранее.
